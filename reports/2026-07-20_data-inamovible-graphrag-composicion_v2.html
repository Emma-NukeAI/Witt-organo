Tres stores separados — la regla de Emmanuel

La “DATA INAMOVIBLE” no es un solo blob. Son tres capas deliberadamente separadas, con contratos distintos. El GraphRAG de este reporte es la capa 2 (más la 1 embebida como Entities).

1 · Identificadores

DATA INAMOVIBLE v1 — genes/accesiones verificados, determinista. 74 records.

analysis/outputs/verified_identifiers.json

Acceso: resolve_id.py · resolve()/require(). NUNCA se inventa un ID; NOT_FOUND es una ausencia positiva.

2 · Corpus RAG (este)

GraphRAG — corpus categorizado en 13 niches × 10 fuentes + embeddings + grafo.

rag_index/ · Neo4j (Dokploy)

Acceso: rag_backend.query() (semántico) vía MCP query_data_inamovible / CLI witt-di query.

3 · Outputs / tesis

Resultados y tesis que los agentes producen (no es fuente, es salida).

SIMULATION_OUTPUTS_DB/ · reports/

Se escriben, se versionan; nunca contaminan las capas 1–2.

🔒 Regla inamovible (ADR-0022)

Toda mutación de las capas 1–2 (ADD/EDIT/DELETE, a través de embedding + índice Neo4j/vector/sparse + raw) pasa por gate humano y especifica qué cambia. Las lecturas son libres (este reporte es una lectura); las mutaciones no. ingest.py es add/update-only (MERGE, nunca borra).

💡 La dualidad niche/db (catálogo ⇄ taxonomía)

Cada niche y cada database existe como dos nodos: un :Document (texto embebido y recuperable — “niche:RN1”, “db:ZFIN”) y un nodo de taxonomía (:Niche/:Database) que sirve de scaffold del grafo. El primero es buscable semánticamente; el segundo ancla las aristas FEEDS/IN_NICHE. Por eso IN_NICHE=16 (13 catálogo→niche + 3 datasets→RN1) y FROM_DB=14 (11 catálogo + 3 datasets).

05

Pipeline de retrieval (READ — híbrido, no-hang)

Una consulta se responde fusionando dos halves: sparse (TF-IDF/BM25 sobre documents.jsonl) y dense (índice vectorial Neo4j + expansión 1-hop del grafo), combinados por Reciprocal Rank Fusion (k=60), y luego rerank. Todo con timeouts acotados: nunca cuelga, nunca devuelve vacío (§6).

QUERY
texto → embed
se embebe con el MISMO modelo del índice (OpenAI 1536) — pin duro
A · SPARSE
TfidfRetriever

B · DENSE
Neo4jGraphRetriever
db.index.vector.queryNodes + OPTIONAL MATCH 1-hop (vecinos)
FUSIÓN
RRF (k=60)
score += 1/(60+rank) por pool · une ambos halves
RERANK
Reranker
NoOp por defecto · cross-encoder biomédico en el rack (opt-in)
MARCA

Escalera de degradación — el arreglo del incidente 07-18/19 (ADR-0039)

degraded = NoneSemántico real: el half dense contribuyó (Neo4j + OpenAI vivos). Score top ~0.80.
sparse-by-configSemántico deshabilitado por configuración (dev/offline, RAG_BACKEND≠neo4j). Hits keyword.
dense-failed:sparse-onlyEl dense estaba configurado pero FALLÓ (Neo4j caído / dim mismatch / MAX_PATH). Sparse enmascarado — se anuncia FUERTE.
sparse (fallback)El path hosted excedió 12s → fallback local sparse (§6 no-hang). Útil pero no de alta-recall.
🩹 Causa raíz del incidente (resuelto)

El MCP corría con un Python sin neo4j/openai (→ siempre sparse) + un deadlock de import de sklearn en thread secundario (→ 1800s). Fix: uv run --locked (intérprete reproducible), preload de sklearn en el main thread, timeout OpenAI 10s, y esta marca de degradación in-band.

06

Embeddings — pluggable por EMBED_MODEL

El modelo de embedding es intercambiable detrás de get_dim()/get_embedder(), y la dimensión del índice siempre se deriva del modelo elegido. En producción (hay Neo4j) el default se fuerza a OpenAI.

openai EN VIVO

text-embedding-3-small · 1536-dim

Default cuando hay NEO4J_URI. Sin infra propia. Timeout 10s / 0 retries (anti-hang).

large → 3072-dim (opt-in)

bge dev/offline

BAAI/bge-base-en-v1.5 · 768-dim

Cero dependencia de API/torch (ONNX vía fastembed). Fallback sin red, sin costo.

biobert · specter2 reserva

sentence-transformers · 768-dim

Embeddings biomédicos (papers). Requieren torch; para el rack.

📌 Decisión (Emmanuel, 2026-06-11)

OpenAI en el servidor para mantenerlo simple (no Ollama). Anthropic no tiene API de embeddings; el 2.º proveedor recomendado sería Voyage AI. Costo de un embed de query ≈ $0.0000004 — el meter grande son los agentes, no los embeddings.
