# Synthetic Data Reference — Mode A

For Mode A (conceptual, no real data provided), the skill generates synthetic scRNA-seq data that mimics the structure of the system being asked about, then runs the requested Squidiff operation on it. This reference contains the generation logic and the marker sets per biological system.

## 1. Why Synthetic Data Is Acceptable for Mode A

The paper itself validates the Squidiff framework on synthetic data generated by Splatter (Fig 1c–g). Synthetic data is not a flaw of Mode A — it is the right tool for the job when the question is "would this hypothesis be worth testing on real data?"

The synthetic data we generate has two properties the gate needs:

1. **Cluster structure** — distinct cell states form separable clusters in latent space (matches Fig 1c)
2. **Marker-gene-driven structure** — the genes that vary across states are biologically meaningful (matches the paper's iPSC differentiation case)

We do not need full Splatter (gamma-Poisson with dropout, library size effects, etc.) for this. A simplified Gaussian mixture in gene-space with structured marker variation is sufficient for the gate's purpose.

The figure produced in Mode A must visibly indicate it is from synthetic data — typically a watermark or caption note. Honesty about the data's nature is part of the substrate-integrity contract.

## 2. The Splatter-like Generation Algorithm

```js
function generateSyntheticData({ systems, states, nCellsPerState, nGenes, markerSets }) {
  // Generates a cells × genes matrix with cluster structure
  // states: ['day_0', 'day_3'] or ['control', 'perturbed'], etc.
  // markerSets: { state_name: ['GENE1', 'GENE2', ...] }

  const totalCells = states.length * nCellsPerState;
  const cells = [];
  const labels = [];
  const geneNames = generateGeneNames(nGenes, markerSets);
  const matrix = [];

  // For each state, draw cells from a state-specific distribution
  for (const state of states) {
    const stateMarkers = markerSets[state] || [];
    const stateMarkerIdx = stateMarkers.map(m => geneNames.indexOf(m));

    for (let c = 0; c < nCellsPerState; c++) {
      const row = new Array(nGenes);
      for (let g = 0; g < nGenes; g++) {
        // Baseline: low expression with some variation
        let mu = 0.5 + Math.random() * 0.5;
        let sigma = 0.3;

        // If this gene is a marker for this state, elevate
        if (stateMarkerIdx.includes(g)) {
          mu = 3.5 + Math.random() * 0.8;
          sigma = 0.5;
        }
        // Random "structure" genes — moderate co-variation
        else if (g < 50) {
          // First 50 genes carry the latent structure for PCA to find
          const stateIdx = states.indexOf(state);
          mu = 1 + 1.5 * Math.sin(g * 0.3 + stateIdx * 1.5);
          sigma = 0.4;
        }

        // Gaussian draw, clamp at 0 (expression is non-negative)
        const val = Math.max(0, mu + sigma * gaussianRandom());
        row[g] = val;
      }
      matrix.push(row);
      labels.push(state);
    }
  }

  return { matrix, labels, geneNames };
}

function gaussianRandom() {
  // Box-Muller
  let u = 0, v = 0;
  while (u === 0) u = Math.random();
  while (v === 0) v = Math.random();
  return Math.sqrt(-2.0 * Math.log(u)) * Math.cos(2.0 * Math.PI * v);
}

function generateGeneNames(nGenes, markerSets) {
  // First include all marker genes, then fill with GENE_NNNN
  const allMarkers = [...new Set(Object.values(markerSets).flat())];
  const names = [...allMarkers];
  for (let i = names.length; i < nGenes; i++) {
    names.push(`GENE_${String(i).padStart(4, '0')}`);
  }
  return names;
}
```

**Defaults that work well:**
- `nCellsPerState`: 300
- `nGenes`: 500 (200 most-variable used for PCA)
- States: 2–6 distinct populations

## 4. State Transition Templates

When the user describes a trajectory or perturbation, map it to one of these templates. Each template defines: which states, which markers, and what Δzsem direction is expected.

### Template: Differentiation along an axis

```
States: state_A → state_B
Δzsem direction: from A's centroid to B's centroid
Marker expectation: A's markers down, B's markers up monotonically along pseudotime
Example: iPSC → definitive endoderm, intermediate mesoderm → renal progenitor
```

### Template: Branching from a progenitor

```
States: progenitor → branch_1 OR branch_2 (mutually exclusive fates)
Δzsem: two vectors, one to each branch
Marker expectation: progenitor markers down, only one branch's markers up per cell
Example: mesoderm aggregate → endothelial OR mural in BVOs
```

### Template: Perturbation response

```
States: control, perturbed (same cell type)
Δzsem: from control centroid to perturbed centroid
Marker expectation: stress-response or pathway-specific markers up; baseline markers may shift
Example: irradiated vs healthy endothelial cells
```

### Template: Drug response (cell-type-specific)

```
States: control, drug_treated for each cell type
Δzsem: separate vector per cell type (effect can differ in direction)
Marker expectation: drug-mechanism-specific markers up/down per cell type
Example: panobinostat on tumor cells vs oligodendrocytes
```

### Template: Rescue / mitigation

```
States: control, perturbed, perturbed + treatment
Verdict question: does treatment Δzsem partially counter perturbation Δzsem?
Marker expectation: damage markers reduced in treated vs perturbed; recovery markers up
Example: G-CSF on irradiated BVOs
```

## 5. Putting It Together — Full Mode A Pipeline

```js
function modeAPipeline(hypothesis) {
  // 1. Identify the system
  const system = identifySystem(hypothesis); 
  // → 'pronephros' | 'BVO' | 'embryo' | 'iPSC' | 'generic'
  const markers = getMarkerSetForSystem(system);
  
  // 2. Identify the template
  const template = identifyTemplate(hypothesis);
  // → 'differentiation' | 'branching' | 'perturbation' | 'drug' | 'rescue'
  
  // 3. Define states
  const states = defineStatesFromHypothesis(hypothesis, template);
  
  // 4. Build marker sets per state from canonical markers
  const stateMarkers = mapStatesToMarkers(states, markers, template);
  
  // 5. Generate synthetic data
  const { matrix, labels, geneNames } = generateSyntheticData({
    states,
    nCellsPerState: 300,
    nGenes: 500,
    markerSets: stateMarkers,
  });
  
  // 6. Run the requested Squidiff operation
  const result = runOperation(matrix, labels, hypothesis.operation);
  
  // 7. Build the figure data
  return {
    panelA: buildLatentEmbedding(matrix, labels, result.deltaVectors),
    panelB: null, // no ground-truth in Mode A; replace with expected-distribution
    panelC: buildDEHeatmap(result.predicted, labels, geneNames),
    panelD: buildMarkerDotPlot(matrix, labels, getMarkerListFromSets(stateMarkers), geneNames),
    panelE: buildPseudotimeDensity(matrix, labels, result.predicted),
    verdict: computeModeAVerdict(hypothesis, result, system, template),
  };
}
```

**Mode A verdict heuristics:**
- If the hypothesis matches a known template AND the system has well-characterized markers AND the operation chosen is appropriate → PASS
- If any of those three fail → MODERATE
- If the hypothesis is structurally incoherent (asking for interpolation between unrelated cell types, perturbation without specifying the perturbation, etc.) → FAIL or NO VERDICT

The Mode A figure must visibly mark "synthetic data — conceptual demonstration" so no one mistakes it for real prediction. Watermark in panel corner, plus the disclaimer in the verdict card, plus the meta line in the header.
