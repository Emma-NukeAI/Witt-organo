## Decisiones / principios nuevos (en CLAUDE.md §7 + memoria)

1. **Gasto operativo AUTORIZADO; mejores modelos siempre.** Usar `claude-opus-4-8` por defecto, `claude-fable-5`
   para lo más exigente; **NUNCA degradar a Sonnet/Haiku para ahorrar**. Se optimiza la **respuesta**, no la
   factura. (Dos medidores: embeddings OpenAI `text-embedding-3-small` $0.02/1M ≈ centavos; **agentes Claude =
   el medidor grande**, p.ej. composite-auditor ≥3 Opus ≈ $1–2.5/corrida.)
2. **Toda mutación de la DATA INAMOVIBLE es human-gated + especificada** — ADD/EDIT/DELETE, sobre embedding +
   índice + raw. `ingest.py` es add/update-only (MERGE, **nunca borra**); pruning = propose→gate→execute;
   cambiar el modelo de embedding **se detiene** pidiendo confirmación. **Reads/refresh libres; mutaciones no.**
   Eso es lo que la hace *inamovible*.

## Cómo operar el loop (referencia rápida)

```bash
# secrets + backend (desde la raíz):
set -a; . .secrets/deploy.env; set +a; export RAG_BACKEND=neo4j

# liveness NO-SPEND:
./.venv/Scripts/python.exe rag_index/graphrag/liveness.py

# responder una pregunta (Path A→B):
./.venv/Scripts/python.exe analysis/scripts/lib/answer_pipeline.py "¿...?" --entities geneA,geneB
#   -> decision_state. Si FALLBACK_FETCHED: correr composite-auditor ≥3 sobre los papers,
#      luego record_audit; si APPROVE -> propose_from_external -> approve_dataset (GATE HUMANO).

# traer un paper:    fetch_paper.py --external "PMID:..."   |   --internal CORPUS-2026-NNNN[#cNNN]
# re-ingesta (gate): approve_dataset.py CORPUS-... --by <humano>   (corre ingest.py)
# pruning (gate):    propose_prune.py  ->  revisar  ->  approve_prune.py <archivo> --by <humano>
```

confirma. Si el primer arranque (uvx en frío) hace timeout: `MCP_TIMEOUT=120000 claude`.
