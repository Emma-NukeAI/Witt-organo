## Decisions

1. **Sesiones unificadas en el ingest (decidido por Emmanuel — el bloque grande).** `_identify()` reemplaza `_auth()` en los 6 endpoints autenticados: **puerta 1** = bearer de sesión del backend (misma tabla `sessions`, `db.validate_token` importado del query_service; necesita `WITT_BACKEND_DB_URL`) — **el firmante se DERIVA de la sesión y el query param `by` se IGNORA** (era falsificable: cualquiera con el token estático firmaba como quien fuera); **puerta 2** = los tokens estáticos (`INGEST_SUBMIT_TOKEN`/`INGEST_ADMIN_TOKEN`) quedan SOLO para scripts CLI, que declaran `by` explícito (400 si falta). Permisos planos: cualquier sesión válida aprueba; la asimetría de cuentas sigue local. Si la BD de identidad está inalcanzable, la puerta de sesión **falla cerrada** y la CLI sigue viva. `/submit` registra `submitted_by` (None = CLI). Códigos exactos: **401** puerta inválida · **400** token estático sin `by` en approve/reject. El camino repo-side (`approve_dataset.py`) no toca HTTP — intacto.
2. **`GET /usage` (M8):** agregación en el SERVIDOR sobre `usage_json` de TODAS las corridas (la lista sirve 50 — un total del cliente no tendría denominador completo): `totals` + `by_user` + `by_model` (costo por modelo re-proyectado con la tabla de precios fechada) + `most_expensive` + ventana `from`/`to` (ISO, inclusive). Tokens = **medición [M]**; dólares = **proyección [E]** con `cost_class`. Los embeds del Rack (consultas `/query`, sin corrida) se sirven aparte como `rack_embeddings` process-wide con su caveat de atribución — declarados, jamás sumados en silencio a los totales.
3. **`epistemic_summary` en la vista de corridas** (`{retrieval_mode, verdict, confidence_state, panel_n_valid}`): derivado **AL CONGELAR** (columna escrita junto al registro; disciplina del contador congelado — servir jamás re-deriva) + **backfill** en la migración para corridas pre-existentes, derivado exclusivamente de valores ya congelados. `null` = corrida sin registro (queued/running/failed sin congelar).
4. **Filtro por nicho en `/query` — existe y es DECLARADO:** `?niche=RNx` filtra una ventana k×4 de candidatos por el `record.data_niche` del binding 1.4 y añade el bloque `filter {niche, applied: "post-retrieval", candidates_considered, note}` con el caveat de recall explícito. Sin `niche`, el sobre sigue siendo espejo verbatim (sin llave `filter`). El filtro a nivel retrieve — el que usarían también CLI/MCP — queda declarado como feature futura de recuperación, no simulado.
5. **`GET /config-history`** (estilo /taxonomia): las entries verbatim + procedencia (ruta+mtime), y los otros dos históricos **DECLARADOS** en vez de silencio: usuarios = tabla `users` (created_at+disabled — estado, no bitácora de eventos; event-log futuro) · `store_version` = git + su serie de ADRs (puerta programática futura).
