## Architecture — "chunks as guide, raw as backing" (ADR-0020 + ADR-0021)

```
Neo4j (guide/index)                         Raw store (durable backing)
  Document / chunk ──raw_ref──►  source-pointer (public: URL+sha256)  OR  MinIO mirror (private/derived)
  Entity (verified ENSDARG)
        ▲                                          ▲
        │ query_data_inamovible / resolve_identifier │ fetch_raw(accession)
        └───────────────── agent ───────────────────┘
                   chunk not enough → fetch the raw
```

- **Embeddings are computed client-side** (OpenAI `text-embedding-3-small`, 1536-dim) at ingest time; the
  server only *stores* vectors. **Methodology lives in git** (`rag_index/graphrag/`) — change it there +
  re-run; never edit anything on the server (it only runs the Neo4j/MinIO/ingest containers).
- **Hybrid raw policy:** public/reproducible sources (ZESTA@CNGB, GSE@GEO) = source-pointer (URL + sha256,
  re-downloadable, not mirrored); private/derived bytes = mirrored into MinIO. The 5.4 GB ZESTA stays
  local in `mcp_cache/zesta/` (gitignored) — only a source-pointer + sha256 is recorded.
- **Anti-fabrication is structural:** only gene symbols already in the verified store (`resolve_id`) become
  entities; unknown IDs are flagged, NEVER minted from memory. (This fixed a prior 15/16 wrong-ID
  corruption — see `docs/findings/2026-06-10-schoels-phase1-id-corruption.md`.)

## How to operate

```bash
# from the repo root, with secrets + backend set:
set -a; . .secrets/deploy.env; set +a; export RAG_BACKEND=neo4j

# verify it's all live (graph counts + a query + a resolve + a raw drill-down):
./.venv/Scripts/python.exe rag_index/mcp_server/server.py   # dev smoke if mcp SDK absent; else runs the server

# add a dataset (repo-side): propose -> review the manifest -> approve+ingest
./.venv/Scripts/python.exe analysis/scripts/lib/add_dataset.py --name "..." --accession GSE... \
    --source-db GEO_NCBI --url https://.../features.tsv.gz --download --niche RN1
#   ...review rag_index/corpus_manifest.json...
./.venv/Scripts/python.exe analysis/scripts/lib/approve_dataset.py CORPUS-2026-NNNN --by "Emmanuel"

# re-ingest the graph (idempotent) after the store/manifest grows:
./.venv/Scripts/python.exe rag_index/graphrag/ingest.py
```

Teammates without the repo use the **hosted service** (`rag_index/ingest_service/README.md`): `POST /submit`
with the submit token → admin `POST /approve/{id}?by=Name` with the admin token (the human gate).

## Gotchas learned this session (so the next agent doesn't re-hit them)

- **Container → Neo4j/MinIO:** the host's *public IP* published ports do NOT hairpin from inside a
  container, and the docker bridge gateway was firewalled. Fix in place: the ingest service **joins the
  Neo4j + MinIO external docker networks** (`rag-emma-mequsz_default`, `rag-datainamovibleminio-grjoil_default`)
  and reaches them by **service name on internal ports** (`bolt://neo4j:7687`, `minio:9000`). If a stack is
  recreated and its network name changes, update `rag_index/ingest_service/docker-compose.ingest.yml`.
- **Port conflicts:** MinIO console `9001` was already taken on the server → remapped to host `9100/9101`.
- **Secrets discipline:** nothing secret in git. `.secrets/`, `.venv/`, `mcp_cache/` are gitignored. The
  5.4 GB ZESTA + the GSE matrix live in `mcp_cache/` (local only).
- **Never push to `polimat-old`.** `origin` = the private `Emma-NukeAI/Witt-organo`.
- **`gh` CLI is not installed** on the user's machine; use `git` + the GitHub REST API (curl) when needed.
